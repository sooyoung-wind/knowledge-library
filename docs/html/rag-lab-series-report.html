5. 개선점 — 다음 사이클의 처방 후보 (효과 크기 순)

  1. 리더 강화 (예상 +15~20p, 최우선) — 32.5%가 여기 묶여 있다. ① 스니펫 600자 절단 해제 (top5 전문 로딩), ② 2-hop 추론용 인스트럭션/CoT, ③ 리더 모델 교체 (glm-4.6 → 더 강한 추론 모델) 순으로 검증. 가장 싸고 가장 크다.
  2. 구원 불가 21질의의 최후 벽 — 다리 엔티티가 코퍼스 어휘 공간에 없음. 처방은 검색이 아니라 문서 확장(하이퍼링크 인접 문서 색인) 또는 사전지식 주입 — 코퍼스 자체를 진화 대상으로 보는 관점 전환 (EnvHarness의 Setup 컴포넌트와 동형).
  3. 리랭커 오담 63골드 — 마진<0.1이 31건. 캘리브레이션(온도/길이 정규화) 또는 앙상블 리랭커. 단 26차가 점수 miscalibration을 실측했으므로 순위 기반 앙상블이 안전.
  4. 라우팅 신호 도메인 일반화 — 마진 신호는 HotpotQA 분포에서 학습된 것. 표적 셋(32차)에선 무효. 신호 후보를 늘려 캘리브레이션셋 분포를 바꿔가며 재검증 필요.
  5. 평가 루프 상설화 — 26차 표적 생성기의 LLM 변동 문제(처방 이득 < 실행 노이즈) 해결: 3회 반복 채택 or 처방-변동 분리 설계.

결론: 루프는 아직 열려 있다. 진화한 평가(26차 표적 셋)가 진화한 시스템(3층)을 여전히 이긴다. "정적 시스템은 정적 벤치마크 통과 후 정체된다"는 EnvHarness 전제가 우리 스택에서도 성립. '진단 → 표적 → 재대결' 사이클 자체가 상설 자산이며, 다음 사이클의 표적은 §5-1의 리더 지형이다.

7. 함정 카탈로그 (7종 — 재사용 가능한 교훈)

  1. 골드누수: 저장 데이터의 rank 필드가 골드만 담으면 가중치가 골드 보너스로 변질 — 재현성 검증도 뚫는다 (25차). 필드 커버리지 확인 전 스코어링 금지.
  2. bind() 미호환: llm.bind(timeout=)는 deepagents 크래시 — ChatOpenAI 생성자의 timeout=이 정답.
  3. 생성 후 속성 무효: httpx 클라이언트는 생성 시점 고정.
  4. 워커스레드 SQLite: deepagents 도구는 자체 연결 필수. "검색 N회 · seen 0" 패턴 = 스레드 버그 신호.
  5. correct+에이전트 손해: 이미 풀린 질의는 재검색으로 흔들림 — 라우팅은 미스 예측이지 이득 예측이 아님.
  6. 진단 표본 CI: 실패 30샘플 진단은 불안정 — 표적 질의 생성은 안정성 검증 필요.
  7. 신호 도메인 의존: 분포가 바뀌면 라우팅 신호의 방향도 바뀐다 (32차).
