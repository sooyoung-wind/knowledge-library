Grafana Adoption Plan

사내 인프라 문제를
보이게 만들기

HDD 용량 부족, GPU 자원 과점유, Docker 컨테이너 중단과 같은 반복 이슈를 사후 대응이 아닌 관측 → 알림 → 원인 추적 구조로 전환하기 위한 Grafana 기초 학습·실습 계획.

Grafana Prometheus Node Exporter NVIDIA DCGM Exporter cAdvisor Alerting
01 · Why

왜 지금 Grafana인가

1

HDD 용량 이슈

디스크가 가득 찬 뒤 발견하지 않고, 사용률·증가속도·임계치를 지속적으로 관찰한다.

2

GPU 사용 이슈

어떤 서버·GPU·프로세스가 자원을 쓰는지 확인하고, 장시간 점유·유휴 상태를 구분한다.

3

Docker 중단 이슈

컨테이너 종료·재시작·CPU/메모리 급증을 탐지하고 장애 시점을 빠르게 특정한다.

02 · Goal

목표는 대시보드가 아니다

“문제가 생겼다”가 아니라
언제 · 어디서 · 무엇이 · 얼마나 이상했는지 바로 확인할 수 있는 운영 구조를 만든다.

CPU, Memory, Load Average, Network, Uptime
05 · Alerting

“보기”에서 “알려주기”로

Disk

80% 경고 / 90% 위험. 임계치뿐 아니라 증가 속도도 관찰.

GPU

장시간 95% 이상 사용, VRAM 고정 점유, 비정상 온도 등 운영 규칙 정의.

Docker

Container down, 반복 restart, 메모리 급증을 즉시 감지.

기초 공부 + 실습 로드맵

07 · Minimal PoC

첫 PoC 범위

대상
사내 Linux AI 서버 1대
수집
CPU / Memory / Disk / GPU / Docker
대시보드
Server Overview + GPU + Docker Health
알림
Disk 80/90%, Docker Down, GPU 이상 상태
검증
고의 Disk 증가, Container stop, GPU load를 발생시켜 탐지 확인
08 · Next

그 다음 확장

Loki

로그 중앙화. Dashboard에서 장애 시점의 로그까지 연결.

Tempo

서비스 간 요청 Trace까지 추적해 장애 원인을 더 좁힘.

Agent

Metrics · Logs · Traces를 읽고 초기 장애 진단을 생성하는 Observer로 확장.

09 · Takeaway

Grafana를 배우는 목적은
예쁜 대시보드를 만드는 것이 아니라,
반복되는 장애를 측정 가능한 문제로 바꾸는 것이다.
