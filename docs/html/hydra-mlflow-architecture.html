Hydra + MLflow 실험 추적 아키텍처

에이전트 주도 실험 환경에서의 config 관리, 결과 추적, 코드 변경 추적 통합 설계 — 2026-05-13

1. 왜 Hydra + MLflow인가

카파시의 autoresearch 패러다임(AI 에이전트가 실험을 자율적으로 설계·실행·평가)에서도, 구조화된 config 관리와 결과 추적은 유효합니다.

도구 역할 데이터 구조 기계적 가치
Hydra 설정(config) 관리 + 실험 실행 YAML → DictConfig → dict 중첩 dict를 flat dict로 변환 보장
MLflow 실험 기록 + 결과 추적 log_params(dict) + log_metrics(dict) API 기반 과거 조회 · 재현 가능
Git 코드 변경 추적 commit hash config로 표현 불가능한 아키텍처 변경 추적
핵심 연결: Hydra의 DictConfig를 flatten하면 MLflow의 log_params()에 그대로 전달 가능. dict → dict 구조적 호환.

2. 전체 데이터 흐름

python train.py model=medium optimizer=adam model.hidden_dim=768

4. Hydra → MLflow 연결 코드

4-1. Flatten 유틸리티

def flatten_dict(d, parent_key="", sep="."):
    """중첩 dict를 flat하게 펴서 MLflow가 받을 수 있게 변환"""
    items = []
    for k, v in d.items():
        new_key = f"{parent_key}{sep}{k}" if parent_key else k
        if isinstance(v, dict):
            items.extend(flatten_dict(v, new_key, sep).items())
        else:
            items.append((new_key, v))
    return dict(items)

4-2. 메인 학습 루프

@hydra.main(config_path="conf", config_name="config", version_base=None)
def main(cfg: DictConfig):
    # 1. Hydra config → 순수 dict
    cfg_dict = OmegaConf.to_container(cfg, resolve=True)
    flat_params = flatten_dict(cfg_dict)

    # 2. MLflow 실험 기록 시작
    with mlflow.start_run():
        mlflow.log_params(flat_params)
        # → model.hidden_dim=512, optimizer.lr=3e-4 등으로 저장

        # 3. Git commit hash 태깅 (코드 추적과의 연결점)
        mlflow.set_tag("git_commit", get_git_hash())

        # 4. 학습
        model = build_model(cfg.model)
        optimizer = build_optimizer(cfg.optimizer)
        for epoch in range(cfg.train.epochs):
            loss = train_one_epoch(model, optimizer)
            val_loss = validate(model)
            mlflow.log_metrics({"train_loss": loss, "val_loss": val_loss}, step=epoch)

        # 5. 최종 결과
        mlflow.log_metric("val_bpb", final_val_bpb)
        mlflow.pytorch.log_model(model, "model")

6. Config 영역 vs 코드 영역

핵심 구분: Hydra로 관리 가능한 영역(하이퍼파라미터)과 코드 수정이 필요한 영역(아키텍처 구조)이 공존합니다.
영역 예시 관리 도구 추적 방식
Config 관리 lr, batch_size, hidden_dim, num_layers Hydra YAML MLflow log_params()
코드 수정 새로운 attention 메커니즘, 학습 루프 변경 Git MLflow set_tag("git_commit")

config로 가능한 것:

num_heads: 8
num_layers: 6
ffn_dim: 2048

7. 통합 아키텍처 요약

에이전트 / 인간 │ ├── [설정 변경] ──→ Hydra YAML 수정/생성 │ ↓ │ Hydra가 config 조합 → dict │ ↓ ├── [코드 변경] ──→ Git commit │ ↓ │ train.py 실행 │ ↓ │ MLflow에 기록: │ params ← Hydra config (dict) │ metrics ← 학습 결과 (dict) │ tags ← git commit hash │ artifacts ← 모델 가중치 │ ↓ └── [결과 조회] ──→ MLflow API (기계) 또는 UI (인간) ↓ 다음 실험 설계 → 루프 반복

8. Karpathy autoresearch와의 관계

카파시의 autoresearch(2026.03)는 Git 기반으로, 에이전트가 train.py를 직접 수정하는 방식입니다. 별도의 추적 시스템 없이 파일과 Git만 사용합니다.

구분 autoresearch (Karpathy) Hydra + MLflow 제안
실험 주체 LLM 에이전트 (Claude, Codex) 동일 + 구조적 추적 레이어 추가
변경 방식 코드 직접 수정 Config는 Hydra, 아키텍처는 코드
추적 Git 히스토리 + 파일 Git + MLflow (params/metrics/artifacts)
과거 조회 파일 읽기 MLflow API (구조화된 쿼리)
스케일 단일 에이전트, 단일 GPU 다수 에이전트 협업 확장 용이
결론: Hydra + MLflow는 autoresearch의 대체가 아니라 보강입니다. 에이전트의 탐색 루프에 구조적 추적 레이어를 추가하여, 인간 검토뿐 아니라 에이전트의 과거 결과 조회도 기계적으로 개선합니다.
